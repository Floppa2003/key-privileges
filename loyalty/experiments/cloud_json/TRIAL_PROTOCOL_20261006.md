# Cohere и Scaleway: ограниченное сравнение — 6 октября 2026

## Цель и границы

Пользователь добавил COHERE_API_KEY и SCALEWAY_API_KEY в GitHub Actions Secrets после предложения проверить альтернативы Qwen. Проверяем по одному ответу каждой модели на четырёх прежних публичных документах. Это эксперимент, не смена выбранного runtime и не разрешение публикации. Qwen, main, сборщики, Google Sheets, расписания и billing не меняются.

Модели закреплены: Cohere `command-a-plus-05-2026` через native /v2/chat; Scaleway `mistral-medium-3.5-128b` через /v1/chat/completions. Никаких автоматических fallback, случайных router, смены ключей или платных подписок.

## Контроль входа и API

Исходники: run 36705324742, прежний plan.json, четыре текста и девять PNG. Порядок: театр, Невский, музей, лавка. Системный промпт, TARGET, текст пользовательского сообщения и все изображения — из текущего merchant_extract.build_request, без обрезки и без редактирования фактов. Полная исходная схема остаётся в пользовательском сообщении и используется при локальной проверке JSON.

В Scaleway меняются только модель, endpoint и нативное `reasoning_effort=high` вместо Kilo reasoning. JSON Schema остаётся той же.

В Cohere `response_format={type:json_object,schema:...}` означает JSON Schema mode, а не schemaless JSON. Единственный перевод ограничения: `minLength:1` заменён на эквивалентный `pattern:[\\s\\S]+`, поскольку Cohere документирует minLength как неподдерживаемый. Это сохраняет непустую строку, включая переводы строк; поле и его смысл не меняются. Любое другое minLength или конфликтующий pattern блокирует перевод. Original schema всё равно проверяется после ответа.

Оба: temperature=1, stream=false, max_tokens=8192. Cohere thinking enabled и token_budget=7168, чтобы оставить 1024 токена для финального ответа; Scaleway reasoning_effort=high. Это сопоставление сервисных конфигураций, не изоляция весов при одинаковом вычислительном бюджете. Специальных правил партнёра, второго LLM и ремонта ответа нет.

## Исполнение и стоимость

На каждого провайдера: один аутентифицированный GET метаданных точной модели, затем до четырёх документов. До двух POST на документ только на явные временные HTTP-ошибки, одинаковое тело, пауза не менее 15 секунд и Retry-After. Указанное ожидание свыше 60 секунд не сокращается: повтор не допускается. Тайм-ауты с неизвестным исходом, ошибки схемы/завершения, 400/401/403/404/402 не повторяются. После неуспеха пакет этого провайдера останавливается. Максимум: 2 GET + 16 POST; обычно 2 GET + 8 POST. Нет фонового повторения.

Cohere публикует бесплатность Command A+ до лимитов даже для production keys. Scaleway публикует первый миллион токенов новым клиентам бесплатно, после — тарификацию. Ключ сам по себе не доказывает оставшуюся квоту. Баланс и фактическое списание не считаются подтверждёнными. Биллинговые настройки не меняем, баланс не пополняем. Это только маленький тест четырёх документов, не массовый сборщик. Из usage записываем только фактически сообщённые показатели; отсутствие поля cost не означает нулевую стоимость.

Секрет каждого провайдера доступен только его inference-шагу. Нет секретов в URL, промптах, request artifacts или git. Redirect отключён. Совпавшие с ключом байты ответа удаляются до сохранения, такой ответ не принимается. В unit-тестах только фиктивная строка.

## Критерии перед просмотром результатов

Сначала отдельно оцениваем доступность API, завершение, соответствие исходной схеме и происхождение цитат. Затем вручную по полному исходнику:

- Театр: ЕКП, 10%, предъявление карты в кассе, выбранные театром спектакли, не более двух билетов на спектакль, не позднее одного дня, без суммирования. Без скриншота с ФИО/документа из Менделеевской карты.
- Невский: 500 баллов за каждую ночь, сайт отеля, номер РЖД Бонус в Комментарий, до 45 суток после выезда. Без неподтверждённого абсолютного запрета остальных каналов.
- Музей: 10% на входной билет в кассе, не сайт/терминалы, без совмещения. Не приписывать явно опубликованный статус выводу о предъявлении карты.
- Лавка: неизвестный размер null, полный перечень категорий книг. Не превращать наличие ЕКП в подтверждённый обязательный способ оплаты; отличать фон программы от конкретной скидки.

Дословное совпадение evidence не равно проверке правильной программы или полноты. Обычный совет показать карту не бракует полезную скидку сам по себе, но неподтверждённые обязательные требования отмечаются. Сырые JSON не исправляются. Четыре знакомых документа и один образец на модель/кейс — не слепая оценка и не надёжность всего каталога.
