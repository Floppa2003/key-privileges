# EKP catalogue preview candidate — not a released source restoration

## Scope and acceptance

This candidate is confined to the already configured anonymous EKP catalogue.
It reads owned rendered cards and clicks the observed `Показать еще` control.
The old generic probe is replaced in the normal `one()` dispatcher on this
branch only. No diagnostic branch, scheduler, credential or Sheets permission
change is included. Do not merge or publish merely because offline tests pass.
Before release, run the actual dispatcher on independent fresh runners, require
current readable cards plus real UI growth, check the public artifacts and
publisher preparation, then separately verify any authorized destination write.
The release version must be advanced before a production release; 2.9.3 on this
candidate is not a declaration that it is already deployed.

## Source structure versus stored answers

The reference is the sanitized public DOM retained by readiness run34958485244,
not a new observation. It has a `Партнеры` title and `.text-h4` heading, a filter
panel also using `.v-card`, responsive duplicate benefit labels and native
`/capabilities/loyalty/tiles/<id>` links. The observed SPA moves from the configured
root to `/capabilities/loyalty/tiles`. Both exact public paths are policy checked.
No fixed partner list, prior benefit values, catalogue length, page count or
fixture text is present in the runtime. Source identities, selectors and resource
bounds are code contracts, not stored partner answers.

A parsed card preserves its own name, benefit preview, full card text, outgoing
link, mixed tags and observed authorization notice. Tags are not guessed to be
categories or applicable regions. No notice means authentication is unknown,
not a verified absence of login requirements. Ambiguous, duplicate, nested,
foreign or credential-bearing card links are rejected; sibling text is not used
to repair missing fields. Same native ID survives changed source text.

## Transport and partial results

The adapter reuses installed_chrome, PublicSource robots handling, challenge
checks and source deadlines. It never imports a user profile, logs in, spoofs
browser properties, disables TLS, uses proxies, or replays private APIs.
HTTP refusals and Retry-After stop reading. HTTP200 challenge bodies are not data.
Both response and final page identity are checked after awaited DOM capture and
again before pagination; the actual resolved path must also pass robots.
Each UI request respects the source interval. Shells and non-growing controls
have finite waits. New snapshots must retain previous IDs and terms.
Already read records survive a later page failure or budget exhaustion.

## Evidence, not certified discounts

The output kind is `source_observation`, status `public_catalog_preview`, and
link kind `page_block`; the direct benefit URL remains null. The observed
outgoing detail link remains in source evidence only. No detail page or private
code is requested. The common normalizer therefore retains the source as
`evidence_only` with no automatic benefits or code components.

The publisher validates scope, kind, text ownership, identity, warnings and
unknown validity. Rehashing a promoted row does not certify an unread detail.
Every populated source report remains partial: `full_catalog_complete=false`
and `details_fetched=false`, even after a load-more control disappears. This
candidate does not reconcile the site's global total or read full partner terms.

## Tests and boundaries

Synthetic tests change names, native IDs, rates, ordering and number of cards.
They cover filter ownership, responsive duplicate labels, tags, authorization
uncertainty, source aliases, malicious promotion, real publisher/common projection,
late navigation, terminal refusals, policy changes at the final URL, request
spacing, repeated/changed pages, deadlines and retention of prior observations.
Mock browser tests exercise the actual walk, not an alternative implementation.
These checks do not prove the source is reachable, that all future layouts work,
or that a user qualifies for any benefit. Reference HTML is test evidence only
and must never be republished with a new observation time.
