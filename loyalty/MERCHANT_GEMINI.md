# Модельный разбор страниц: Gemini напрямую

С 3 октября 2026 выбранный вход модельного этапа — `merchant_extract.py`, модель `gemini-3.8-flash`, прямой Google Gemini API. Это изменение в ветке PR #90. Ежедневный детерминированный сборщик `collect_normalized.py`, его расписание и публикация в Sheets не переключаются и не вызывают этот модуль автоматически. Общий PR не сливается этим изменением.

## Запуск

```sh
python -m pip install -r loyalty/merchant-requirements.txt
# Без ключа и без сети: проверить все источники и сохранить подготовленные запросы.
python loyalty/merchant_extract.py --manifest inputs/manifest.json --out prepared
# Выполнить разбор; GEMINI_API_KEY задаётся через окружение / Actions Secret.
python loyalty/merchant_extract.py --manifest inputs/manifest.json --out results --execute
```

Директория вывода должна быть новой. Нет аргумента для передачи ключа, случайного router, Kilo/Ollama fallback, второго LLM или автоматического исправления JSON. Исторические сравнения остаются в `experiments/`; они не являются выбранным рабочим входом.

## Вход

Подготовленные полные изображения страницы и весь извлечённый текст передаются отдельно для каждого документа. Манифест — объект `{"documents": [...]}`. Элемент содержит:

```json
{
  "id": "partner_program",
  "target": {"partner": "Партнёр", "program": "Программа", "as_of": "2026-10-03"},
  "text": "partner/visible-text.txt",
  "images": ["partner/page-1.png", "partner/page-2.png"],
  "sha256": {
    "partner/visible-text.txt": "<SHA256 байтов текста>",
    "partner/page-1.png": "<SHA256 PNG>",
    "partner/page-2.png": "<SHA256 PNG>"
  }
}
```

Пути относительно манифеста, только внутри его директории. Все хеши обязательны и проверяются до вызовов. PNG идут в указанном порядке; соседние программы и фон страницы не вырезаются. `as_of` — дата оценки источника, не окончание акции. Дополнительные поля элемента (например, URL, время и предупреждения захвата) сохраняются в `input.json`, но не становятся инструкциями модели.

Предохранители: 1–30 документов, 1–40 PNG на документ, текст до 500000 символов, суммарные исходные байты документа до 14 МБ, тело HTTP до 20 МБ. Превышение — ошибка, а не обрезка. Сам модуль не ищет сайты, не делает OCR и не преобразует произвольный HTML/PDF; он принимает уже подготовленные полные PNG/текст от этапа захвата.

## Запрос и результат

Промпт `merchant_prompt.txt` и схема `merchant_offer.schema.json` перенесены без смысловых изменений из проверенного облачного опыта. На четырёх замороженных документах проверено равенство тел запросов до/после переноса. Температура 1, thinking HIGH, максимум вывода 8192, одна конечная кандидатура. JSON Schema присутствует и в сообщении, и в `responseJsonSchema`.

Сохраняются текст, все PNG, их упорядоченный манифест и хеши, запрос без дублирования base64, сырые ответы каждого HTTP-вызова, метрики и `extracted.json`. Последний создаётся только для STOP нужной модели, корректной схемы и согласованного `has_offer`. Запрещены подмена итогового ответа рассуждениями, дублирующиеся JSON-ключи и нечисловые/бесконечные числа. `how_to_get` остаётся названием поля действий; модуль не преобразует результат в публикуемые строки Sheets.

`schema_valid` означает только проверку структуры. Принадлежность условий программе, корректность выводов, полноту захвата и дословность цитат нужно оценивать отдельно. Всегда `publication_allowed=false`, `semantic_review=pending`.

## Временные ошибки

Один логический разбор может содержать максимум три HTTP-попытки, только при 408/429/500/502/503/504. Повторяется точно то же тело, без новой подсказки и без смены модели. Ожидания 15 и 30 секунд плюс 0–3 секунды случайной добавки; `Retry-After` и Google RetryInfo — нижняя граница ожидания. Если сервер просит ждать более 60 секунд или новая попытка не укладывается в бюджет допуска 300 секунд, документ получает `deferred`, без обхода лимита.

Тайм-аут соединения/чтения сохраняется как неизвестный исход запроса и автоматически не повторяется. Ошибки доступа и некорректный ответ модели также не повторяются. Бюджет 300 секунд ограничивает допуск новых ожиданий/попыток; это не отдельный жёсткий таймер всего HTTP-потока. Сокеты имеют отдельные тайм-ауты, job Actions — общий предел.

После неуспеха прекращается пакет; уже готовые результаты сохраняются, оставшиеся ID перечисляются в `not_attempted`. Автоматической фоновой очереди или расписания повторов нет. Код выхода неполного пакета — 2. Не следует перезапускать весь пакет только ради повторения уже хороших ответов: новый манифест должен содержать только нужные документы.

## Безопасность и стоимость

Ключ только в `x-goog-api-key`, не в URL/теле/артефактах; redirect запрещён. Ответ с буквальным отражением ключа редактируется для хранения и не принимается как извлечение. Проверка отсутствия ключа выполняется перед сохранением итоговой сводки. Не включаются billing, платный fallback или иные сервисы. Фактический тариф Google-проекта задаётся владельцем аккаунта и не определяется этим модулем; наличие ключа не доказывает нулевое списание.

## Проверка перехода

`merchant-gemini-direct.yml` запускает регрессионные тесты на соответствующие изменения в рабочей ветке. Живой ограниченный тест запускается только отдельным `workflow_dispatch` или коммитом с `[gemini-smoke]`. Он использует текущий `merchant_extract.py`, а не старый экспериментальный клиент: по одному логическому разбору четырёх замороженных кейсов, максимум 12 POST, без GET/смены модели. Артефакты источников для этого теста временные; обычный CLI от них не зависит.

Документация провайдера, проверена 03.10.2026:
- https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash
- https://ai.google.dev/gemini-api/docs/troubleshooting
- https://ai.google.dev/gemini-api/docs/structured-output

Результаты реального запуска фиксируются отдельно после его завершения, не предполагаются заранее.
